## 1 工作方法论与完成定义

### 1.1 打勾与留痕

每个 `P阶段.序号` 是最小执行、审核和提交单位。任务内编号步骤是操作说明，不单独计进度；若把其中一步升级为独立 `[ ]` 子项，须同步添加到执行树并单独审核、留痕、提交。每次只执行一个最小任务；如仍过大，在开始前拆为独立编号，不以批量完成替代逐项提交。

完成任务必须同时更新执行树与任务详情：`[ ]` 改为 `[x]`，附 `✓ + 完成时间 + 一句话结果`，并在该任务末尾追加完成记录。没有时间戳的记录无效，不计入进度。不得把“代码已运行”“报告已生成”直接视为验收完成。

### 1.2 单点闭环

1. 写入任务开始时间，核实依赖、输入版本与验收标准。
2. 在工作区执行任务，形成详细报告：做了什么、怎么做的、参数、数据结果、结论及局限。
3. **先审后记**：派独立 subagent 审核代码、数据、结论与验收条件。通过前不得正式打勾、记为完成或提交最终结果。工作区中间文件与审核草稿可以保存，须标注未验收。
4. 按审核意见修改并复审。审核不通过不得开始下一个最小任务；subagent 不可用时记录阻塞并讨论替代审核方式，不以自审冒充独立审核。
5. 审核通过后，更新执行树、任务详情与完成记录；提交 `TODO.md` 变更、本次代码/配置、报告及结果。大文件按已确认存储策略提交清单、校验值和获取路径。
6. **一个最小任务一个 git commit**。未 commit 视为未完成，不得进入下一项。提交标题包含任务 ID；用 `git log --grep` 对应任务 ID 查找哈希，避免为向同一个提交写入其自身哈希形成循环。下一条进度记录可补记前一任务哈希。
7. 需要 `/compact` 时，先写详细 handoff 并保存为 `logs/handoff_<YYYYMMDD_HHMM>.md`，再压缩；恢复第一步读取最新 handoff，核对 TODO、提交与数据版本，再继续。

### 1.3 Phase 里程碑

每一 Phase 全部最小任务通过审核并提交后，输出里程碑报告，附各任务开始/完成时间、结果摘要与提交。发群讨论，经用户/负责人确认后才进入下一 Phase。

本 TODO 记录该规则，不代表已授权自动向外部群聊发消息。执行时先准备可发送报告；在已有明确发送授权且指定目标群时发送，否则请用户转发或确认发送目标。Gate 状态可依次为：未开始 → 执行中 → 待讨论 → 已确认。

### 1.4 讨论纪律

遇到结果异常、数据问题、决策点、样本不足或故事主线偏离，先写时间戳、证据、影响、选项和建议，讨论后行动；不得擅自换标签、降低验收标准、改保留集或扩大结论。讨论记录写入 `logs/decisions.md`，批准的范围变更同步到 TODO、配置与曝光清单。

### 1.5 时间与版本纪律

执行树、任务记录、审核、进度更新、Phase 里程碑和 handoff 都必须包含分钟精度时间戳；跨日时开始与完成均写完整日期。`TODO-0` 对应项目初始化任务 `P0.01`，核查已有仓库，不覆盖现有未跟踪文件。所有 `[ ]` 条目完成后逐项提交，不攒批。原截图提到的“2026-09-03 用户明确”只作为规则来源文字，不作为本项目已发生的授权或完成证据。

预测表最少保存 `run_id, task_id, sample_id, group_id, split, seed, y_true, score, valid_mask`；残基任务加 `residue_index`，多类任务加固定类别顺序和各类分数。训练期预测与验证/测试预测明确区分。标签受访问限制时，预测表按对应集合权限存放。

### 6.4 数据行如何人工核对

先验证原始出处，再检查结构/序列/构建体一致性，最后检查标签坐标和条件。常规记录按预先写定的抽查规则检查；所有冲突、映射不唯一和异常记录逐条复核。每次复核保存样本 ID、证据定位、检查人/代理、时间及结论。此处不指定虚构的抽查数量，由数据规模和错误风险决定并留痕。

同一序列可以对应多个状态样本，但它们属于同一配对或蛋白分组；同一实验的多个时间点、结构链或重复测量不能增加独立蛋白数。缺失标签与真实负标签必须在存储、损失和评价三处保持一致。

| 情况 | 当前动作 | 恢复条件 |

| 缓存、坐标或 ID 不一致 | 停止受影响运行，保留日志并定位版本 | 修复后重建相关产物并复核 |
| OOM 或运行中断 | 保存失败参数，先判断批大小调整是否改变数值/目标 | 在已允许策略内重跑；方法变更另行确认 |
| 置换无变化或对照泄露 | 禁止引用该对照结论，检查可交换单位 | 重新注册合适方案、审核后再跑 |
| 确认反馈引发修改 | 降级已曝光确认批次并重新打开相关任务 | 新未见确认集、重新注册和确认 |
| 保留集结果不理想 | 完整报告失败或不确定性 | 不以同一保留集调参后继续声称未见验证 |
| 审核不通过或提交失败 | 保持未完成、修正/重审/重新提交 | 审核通过且本任务提交成功 |
